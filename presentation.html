Slide 2 — Introduction: The Context Bloat Crisis

Problem Analysis
⚠️ The "Load-All" Anti-Pattern in MCP

The Model Context Protocol (MCP) standardizes how AI coding agents connect to external tools. However, current client implementations rely on an unscalable naive approach:

  • Upfront Static Preloading: Every connected server’s complete JSON Schema is dumped directly into the system prompt upon initialization.
  • Explosive Token Overhead: Connecting 10–20 downstream servers (GitHub, Playwright, DB, Filesystem) injects 21,800+ tokens before the user types a single prompt.
  • Stateless Re-transmission: Because LLM APIs are stateless, this 21.8k schema payload is re-transmitted on every single turn and sub-step.
45.0k Context - 23.2k Base = 21.8k Wasted Schemas
Empirically verified in OpenCode: MCP tools account for nearly 50% of the entire prompt window!
⚡ Triple Failure Modes & Proposed Solution
1. Tool Confusion & "Lost in the Middle":

When faced with 60+ tool definitions, LLMs pick wrong tools, hallucinate arguments, and lose focus on user requirements.

2. Rapid Context Exhaustion:

Forces early conversation compaction, wiping out vital debugging logs, code diffs, and conversational history.

3. The Solution: Dynamic Meta-Tool Gateway:

Replace static preloading with Just-In-Time (JIT) retrieval, exposing only two meta-tools: discover_tools and invoke_tool.

Slide 4 — Scope of the Study

System Boundaries
✅ In-Scope System Boundaries
  • Protocol Conformance: Complete support for Anthropic Model Context Protocol specification (Draft 2024-11-05) across both stdio and SSE transports.
  • Multi-Server Ecosystems: Seamlessly manages 8 to 20 concurrent downstream tool servers (GitHub, Filesystem, Playwright, Memory, SQLite, etc.).
  • The Tool Schema Layer: Explicit mathematical isolation and optimization of the MCP Tool Schema footprint across single-turn and multi-turn coding sessions.
  • Project Context Awareness: Automated workspace AST and manifest parsing (extracting dependencies from package.json, pyproject.toml, requirements.txt).
  • Transparent Hot-Reloading: Automated file modification timestamp (mtime) polling for downstream configuration changes.
🛡️ Assumptions, Limits & Client Baselines
  • Fixed Client Baseline Separation: The study explicitly isolates MCP tool schemas from client-native overhead (e.g. OpenCode’s 148 skills catalog or user rules), showing where savings apply.
  • Quantized CPU Inference: Relies on lightweight dense embeddings (all-MiniLM-L6-v2, 384 dimensions) to eliminate GPU infrastructure requirements.
  • Deterministic State Machine: Utilizes LangGraph to prevent infinite agent recursion or nondeterministic cycle loops during tool discovery.
  • Standardized Benchmark: Empirical evaluations conducted over a 20-task multi-domain testbed measuring precision, recall, F1, latency, and task completion.
Key Scope Takeaway:

MCP Orchestrator does not rewrite the agent’s reasoning engine; it serves as an intelligent middleware filter that shields the agent from schema bloat.

🔍 Hierarchical Two-Stage Retrieval

Flat vector search produces false positives across unrelated domains. Orchestrator implements coarse-to-fine pruning:

  • Stage 1 (Server Level): Queries ChromaDB servers collection with query vector vq. Extracts Top-N candidate servers (N=3).
  • Stage 2 (Metadata Constrained): Queries tools collection with strict boolean SQL/Chroma filter: WHERE server_id IN [candidates].
  • Resilient Fallback: If ChromaDB is unavailable, Stage 1 gracefully falls back to lexical TF-IDF keyword scanning.
📐 3-Term Context-Aware Weighted Ranking
Score(t) = w₁·QuerySim + w₂·ProjMatch + w₃·PastSuccess
Subject to: w₁ + w₂ + w₃ = 1.0 (w₁=0.25, w₂=0.70, w₃=0.05 optimal via LOO-CV)
  • QuerySim: Cosine similarity between query and tool description vector ∈ [0, 1].
  • ProjMatch: Semantic alignment between tool and project dependencies vector ∈ [0, 1].
  • PastSuccess: Bayesian empirical reliability: (Success + 1) / (Total + 2) (Cold-start = 0.50).
  • Relevance Filter: If max(QuerySim) < 0.15, returns empty list to save tokens on chat.
